# Socratic Learn 재방문·홍보 실험

기준일: 2026-09-28. 상태: 구현 및 게시물 초안 준비, 미배포·미게시·미집행.

## 합의와 범위

- 기존 서비스를 배포하고 피드백을 받았으나 사용자가 돌아오지 않았다. 접속 장애였다는 근거는 없다.
- 초기 대상: 개발 공부 중인 대학생·취업 준비생. 첫 메시지는 현재 로드맵과 맞는 안드로이드 학습자로 좁혀 실험한다.
- 무료 홍보 우선, 유료 홍보 상한 50달러. SNS 계정은 Instagram·LinkedIn·Threads 모두 보유. 계정 URL·이전 피드백 상세·최종 게시 문안은 확인 대기.
- 사용자 승인으로 `codex/landing-product-first`에서 기존 소개 페이지 개편에 이어 작업한다.
- 저장소 실제 코드와 이번 대화가 기준이다. 예전 문서의 인증·서버 저장 미지원 설명은 현재와 다르다.
- 기존 소개 페이지의 상단 CTA는 유지. 완료를 실력 상승으로 표시하지 않는다. 새 재방문 기능, 강제 로그인, 자동 DM, 유료 광고, 임의 후기·효과 수치는 추가하지 않는다.

## 판정 기준

캠페인 게시 후 14일을 첫 실험 기간으로 잡는다. 20명 체험, 10명 첫 피드백 노출, 3명 재사용은 운영자가 정한 임시 목표이며 시장 평균이나 예측치가 아니다. 실제 집계 전 상태는 0이 아니라 미확인이다.

- 체험자: sl_learning_created를 발생시킨 고유 사용자.
- 활성화: 체험자 중 sl_feedback_viewed가 있는 고유 사용자. 이벤트 횟수가 아닌 사용자 수로 계산한다.
- 7일 내 재사용: 첫 피드백 체험 후 24시간 이상, 7일 이내에 다른 learning_session_id의 sl_learning_created가 있는 사용자. 7일 관찰 기간이 지난 코호트끼리 비교한다.
- 학습 흐름 이탈: entry_view → start_attempt → learning_created → answer_submit → feedback_viewed. 시작 시도는 인증 전이라 learning_session_id가 없다. 이벤트 시간과 사용자 식별 범위 안에서 해석한다.
- 채널 비교: 조회수·좋아요와 별도로 활성 사용자 수, 재사용자 수를 본다. 첫 표본은 원인 인터뷰를 우선하고 비율 차이를 통계적 우열로 단정하지 않는다.

새 생성·피드백 이벤트는 학습 식별자로 learning_session_id를 사용한다. 기존 이벤트의 session_id와 값은 같지만 이름을 구분해 분석 도구의 방문 세션과 혼동하지 않는다. 보고서는 원시 파라미터와 이벤트 이름을 함께 확인한다. 과거 sl_session_start는 learn 진입 이벤트이므로 시작 버튼 클릭 지표로 쓰지 않는다.

커스텀 campaign_*는 이번 캠페인의 허용 값만 전송한다. 같은 탭에서 최신 UTM을 유지하고 URL 쿼리가 없는 내부 이동에 전달한다. 브라우저의 탭 복제/복원은 sessionStorage를 복제·보존할 수 있으므로 엄밀한 광고 기여도 모델은 아니다. GA의 자동 page_location 수집과 별개이며 개인 정보는 UTM에 넣지 않는다.

피드백 노출은 화면에 일부라도 보이고 탭이 활성 상태인 때를 뜻한다. 정독·납득·학습 효과를 증명하지 않는다. 같은 탭의 같은 학습에서는 한 번만 기록하지만 다른 탭·저장 실패·분석 차단이 있으므로 보고서에서도 중복 제거한다. 익명 사용자의 브라우저 변경·기록 삭제, 로그인 전후 식별 변화와 분석 차단으로 누락될 수 있다.

## 첫 운영 순서

1. 코드·공유 이미지 검증 후 배포 범위 승인. 실제 배포와 GA 수집을 확인한 다음 게시한다.
2. 기존 사용자 피드백 상세를 회수해 재방문하지 않은 이유를 분류한다. 사용자에게 연락하는 메시지는 별도로 확인 후 보낸다.
3. 스레드 질문 글 한 건과 링크드인 제작 배경 글 한 건을 먼저 게시한다. 인스타그램 카드 4장은 프로필 링크 확인 후 게시한다.
4. 각 게시물의 24시간·72시간 결과를 `results.csv`에 기록한다. 운영자가 직접 댓글에 답한다. 자동 대량 답글이나 추천 요청은 하지 않는다.
5. 7일 관찰이 끝난 사용자들의 재사용 여부를 확인하고, 하루 내 이탈한 사람과 돌아온 사람의 사용 이유를 비교한다.
6. 노출은 많은데 클릭이 없으면 메시지·독자 적합성, 시작은 많은데 피드백이 적으면 대기·질문 부담·오류, 피드백 후 재방문이 없으면 반복 사용 목적을 조사한다. 원인이 확인되기 전에 알림 기능부터 만들지 않는다.

## 예산

현재 집행액: 0달러. 우선 무료로 검증한다. 필요하면 인터뷰 사례비 최대 20달러, 반응이 확인된 콘텐츠의 유료 테스트 최대 30달러라는 배분을 제안하되 아직 집행 승인으로 보지 않는다. 긍정 후기나 추천을 보상 조건으로 삼지 않는다. API·Firebase 운영비는 별도이며 실제 청구액·한도를 확인해야 한다.

`functions/src/usageLog.ts`에는 요청별 추정 비용 로그가 있다. 이는 모델 단가 표에 의존한 추정치이며 청구액이 아니다. 현재 로그에는 학습 session_id가 없으므로 세션당 비용을 정확히 연결할 수 없다. 검증 기간 합계 / 같은 기간 생성·완료 학습 수는 대략적인 운영 지표로만 사용한다. 공급자 지출 상한, Firebase 예산 알림 설정 상태는 미확인. UID별 요청 제한만으로 전체 지출 상한을 보장하지 않는다.

2026-09-28에 gcloud CLI로 socratic-learn-web 프로젝트의 최근 30일 로그를 `jsonPayload.message="llm_usage"` 조건으로 조회했다. 최대 1,000건 중 일치 결과는 0건이다. 이는 그 조건에서 로그를 찾지 못했다는 뜻이며 실제 비용·사용량이 0이라는 뜻이 아니다. 청구액과 공급자 상한은 계속 미확인이다.

브라우저 점검 재실행: 로컬 앱을 5189 포트로 실행한 뒤 저장소 루트에서 `node frontend/e2e/growth-smoke.cjs`. `evidence/`의 화면은 테스트 데이터이며 사용자 후기나 실제 AI 답변 증거가 아니다.

확인된 품질 문제 중 완료 시 초기 수준에 1을 더해 실력이 오른 것처럼 표시하던 부분은 제거했다. 과거 사용자가 떠난 원인은 아직 확인하지 못했으므로 이 수정이 재방문을 개선했다고 주장하지 않는다. 실제 AI 피드백 품질, 응답 대기 시간, 반복 사용 목적은 체험과 인터뷰로 확인해야 한다.

구조상 `frontend/src/App.tsx`의 AppWorkspace는 인증·세션 시작·저장·라우팅·학습 화면 조합을 함께 맡아 단일 책임 원칙(SRP)에 어긋나는 변경 집중 지점이다. 이번에는 피드백 노출 측정과 유입 측정을 별도 컴포넌트로 분리했으며, 전체 워크스페이스 리팩터링은 별도 범위로 남긴다.
